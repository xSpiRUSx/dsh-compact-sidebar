# Компактный интерфейс

Самостоятельный UI-плагин `@local/dsh-compact-sidebar`:

- скрывает логотип и название DeepSeek Harness слева сверху;
- освобождает место брендовой строки, сохраняя кнопку сворачивания;
- уменьшает область рабочих пространств и тредов до **90%**;
- собирает «Плагины», «Автоматические задания» и остальные глобальные панели в горизонтальную строку **только иконок** над воркспейсами;
- заменяет отдельную широкую кнопку новой сессии компактной **«+ New»** первой в том же ряду (68 × 32 px); это та же штатная кнопка с прежними правами доступа, горячей клавишей и действием, без дублирования создания сессий;
- сохраняет штатные кнопки, доступные имена (`aria-label`), подсветку выбора, клавиатурную навигацию и меню «Ещё»; при нехватке ширины строка прокручивается горизонтально;
- не меняет масштаб чата, содержимое глобальных панелей и нижние настройки;
- добавляет произвольные сохраняемые группы проектов; папки и принадлежность сессий не изменяются;
- сохраняет штатный список как отдельный режим, его сохранённый ручной порядок и раскрытия не очищаются фильтрацией групп.

## Панели и меню «Ещё»

В версии 1.4.0 иконки занимают по 32 px без пустого места под скрытые кнопки открепления. В штатном меню «Ещё» добавлен раздел **«Закреплённые панели»**: выберите «Открепить» рядом с нужной панелью. Открытие и возврат скрытых панелей выполняются прежними штатными пунктами DSH. «Плагины» остаются закреплены по правилам самого DSH. Если штатная часть меню для скрытых панелей отключена или завершилась ошибкой, наш раздел показывает также действие «Закрепить» для скрытых панелей: их можно вернуть в строку без перезапуска.

Используются переданные владельцем меню `entries`, `onPinnedChange` и `onDismiss`, без собственного списка закреплений или операций над Host. Состояние закрепления остаётся штатным состоянием DSH и может сбрасываться при его перезагрузке. При ошибке меню не выдаёт успех и показывает сообщение. Если регистрация нашей части меню недоступна, исчезла или завершилась ошибкой компонента, штатные кнопки открепления возвращаются вместе с необходимым для них местом.

Над зарегистрированными иконками панелей отображаются обычные браузерные подсказки с текущим локализованным названием. Их компоненты декорируются через реестр Slots с сохранением исходных ID, порядка, меток, данных и действий. Дополнительных кнопок или остановок Tab не появляется; для клавиатуры сохраняются доступные имена штатных кнопок. Это не замена штатного тултипа на клавиатурном фокусе.

## Группы проектов

После полного перезапуска нажмите новую кнопку с иконкой групп **рядом с настройками внизу боковой панели** (подсказка «Настроить группы проектов»).

1. Создайте группу, например «Работа» или «Инструменты».
2. В разделе «Распределение проектов» выберите группу для каждого проекта. Путь к проекту виден в подсказке.
3. Режим «Использовать мои группы» включается при создании группы. Название группы в списке раскрывает её; одновременно открыта одна группа.
4. Внутри открытой группы работает штатный браузер DSH: проекты, треды, контекстные меню, поиск и добавление проектов. Поиск ограничен открытой группой; «Без группы» также включает сессии без зарегистрированного воркспейса.
5. Кнопка «Стандартный список» в шапке групп или снятие флажка возвращает обычный список и его Workspace Tree. Группы при этом не удаляются.

Группы можно переименовывать и удалять. Удаление группы возвращает её проекты в «Без группы» и **не удаляет** ни проекты, ни сессии, ни каталоги. Новые проекты первоначально попадают в «Без группы». Проекты, временно отсутствующие в каталоге DSH, сохраняют своё распределение и восстанавливают его при возвращении.

Названия, распределение и раскрытие пользовательских групп сохраняются в собственном ключе localStorage текущего браузера/адреса GUI. Они переживают перезапуск с тем же origin, но не синхронизируются между браузерами, адресами сервера или устройствами. При недоступном хранилище показывается ошибка, успешное сохранение не имитируется. Повреждённые или более новые данные не перезаписываются; сброс выполняется только отдельной кнопкой с подтверждением.

Настройки вида **внутри** группы (Workspace/Workspace Tree/flat, сортировка, фильтр архивов и ручной порядок) изолированы от обычного списка и хранятся в памяти отдельно для каждой группы до перезапуска. При переключении группы локальный поиск и пагинация штатного браузера могут сбрасываться. Это предохраняет обычный список: штатный `retainAccountKeys` не должен считать скрытые фильтром проекты удалёнными.

## Совместимость

Слоты `sidebar.brand.mark` и `sidebar.brand.name` используются через публичный API Cordis. Для высоты брендовой строки, горизонтального расположения навигации и масштаба списка публичного API нет: CSS-адаптер версии 1.4.0 проверен по исходникам и классам `ui-sidebar` **0.2.2-rc.2**. Он учитывает новую вложенность `scrollRegion > scrollArea > panelList / regionArea`: два уровня CSS subgrid сохраняют DOM, штатные обработчики и выделяют оставшуюся высоту списку проектов. Контейнер размеров для браузера находится на его собственной области. После обновления DSH адаптер может потребовать повторной проверки.

Все правила компактной геометрии ограничены наличием этой структуры и маркера `data-sidebar-scrollport`; без неё или поддержки subgrid сохраняется штатная раскладка. Это защита от известного частичного совпадения старых классов, а не гарантия совместимости с любыми будущими версиями DSH. При работающей части меню «Ещё» отдельные кнопки открепления в строке скрываются; при её недоступности сохраняется безопасная штатная альтернатива.

В Web над списком остаётся компактная строка для кнопки сворачивания. На Windows Desktop кнопка остаётся в системной шапке, а пустая брендовая строка получает нулевую высоту. На macOS сохраняется отдельная полоса системных кнопок. Свёрнутая панель не масштабируется.

Стили — React-элементы собственных компонентов: при выключении или выгрузке плагина они удаляются, штатные слоты восстанавливаются. Нет прямых DOM-изменений, monkey-patching, таймеров, runtime-зависимостей от других локальных плагинов или машинных путей. Группы меняют только UI-предпочтения; операции над сессиями выполняет исходный штатный браузер.

Адаптер групп использует текущую запись `sidebar.workspaces` из реестра Slots (метод `entries`, которым пользуется сам `ui-workspace`), её исходные компонент, inject-функцию, дочерние слоты и locale. Подменяются только каталоги видимых воркспейсов/сессий и отдельный **непостоянный** store настроек вида. Настоящие ID и пути не подменяются; синтетические Host-воркспейсы не создаются. Это адаптер к внутреннему контракту `ui-workspace`, проверенному на **0.2.2-rc.1 и 0.2.2-rc.2**, а не универсальный публичный API группировки. Если нужный контракт отсутствует, режим недоступен, но оригинальный список остаётся. После обновлений DSH требуется повторная проверка.

Иконка — оригинальный SVG этого пакета. Метаданные доступны на русском и английском.

## Проверки

Из корня этого пакета:

```powershell
node build-client.mjs
node build-client.mjs --check
node --check index.js
node --check client.js
node --test
```

Проверки статические: они не заменяют осмотр реального интерфейса. После установки проверить раскрытую и свёрнутую панель, светлую/тёмную тему, поиск, прокрутку, меню и отключение плагина. Для строки иконок проверить открытие каждой панели, выбранное состояние, Tab/Enter, меню «Ещё» и доступ к последним кнопкам при узкой ширине. CSS-адаптер нужно отдельно проверить после обновления DSH.

## Установка

1. Включите в DSH опциональный встроенный пакет пользовательских индексов (**Custom plugin indexes**), если вкладки **Discover** ещё нет.
2. В **Плагины → Discover → Добавить источник индекса** укажите `https://raw.githubusercontent.com/xSpiRUSx/dsh-compact-sidebar/main/market-index.json`.
3. Найдите **Компактный интерфейс** (`compact-sidebar`) и нажмите **Установить**. В пресете с доступом к `plugin_market` можно также попросить агента установить `compact-sidebar` из подключённого индекса.

DSH устанавливает версию с точного Git-коммита. При следующей загрузке или ручном обновлении Discover будет предложена более новая совместимая версия из индекса. Установка с ветки, тега или локального каталога не поддерживает обновление из индекса: локальную копию с тем же именем пакета нужно сначала удалить в менеджере DSH, затем установить заново из Discover. При необходимости перезапустите DSH по подсказке менеджера.

Пакет не заменяет и не редактирует существующий `dsh-better-sidebar`. Если другой плагин занимает брендовые слоты с приоритетом -10 или меньшим (в этой версии меньшее число выигрывает) или полностью заменяет боковую панель, совместимость нужно проверить до включения.

## Публикация новой версии

1. Измените `version` в `package.json`, проверьте `engines.dsh` для поддерживаемых версий DSH, выполните `npm run build` и `npm test`.
2. Закоммитьте файлы плагина в `main` и поставьте тег `vMAJOR.MINOR.PATCH` на этот коммит. Теги опубликованных версий не перемещайте.
3. Выполните `npm run update-index` и закоммитьте `market-index.json` отдельно. Генератор берёт версии и точные Git-коммиты из тегов в истории `main`.
4. Отправьте `main` и новый тег, например `git push --atomic origin main v1.4.2`. GitHub Release можно оформить отдельно: DSH читает индекс, а не список релизов.
